## 3. STATE TRANSITIONS

**FACT** — Version status transitions:
```
(active, first version) → (active, no promotedFrom)
(rolled-back) ← → (active)   via rollbackVersion()
```

**FACT** — Candidate status transitions:
```
draft → benchmarked   (via evo_benchmark_run or evo_benchmark_live)
draft → rejected      (benchmark thresholds not met)
benchmarked → promoted (via evo_promote)
benchmarked → rejected (via promotion policy failure or manual)
promoted → (terminal)
rejected → (terminal)
```

**FACT** — Experience records: append-only, no update path exists. Each gets a unique `newId()` UUID.

**FACT** — Pattern records: append-only, deduplicated by description string match.

**FACT** — BenchmarkRun records: append-only, no dedup or cleanup.

**FACT** — `evo_promote` execution order (BUG):
1. `materializeArtifact` (writes artifact)
2. `validateArtifact` (static check)
3. `activateVersion` (pre-flight + **mounts into host**) ← **MOUNTS BEFORE POLICY GATE**
4. `runPromotionPolicy` (beats_active gate)

**CRITICAL BUG** (`src/host/modules/promote/tools.ts:66→84`): If `activateVersion` succeeds but `runPromotionPolicy` rejects, the candidate's tool is already mounted in the host with no version record. The mount is never reverted on policy failure.

## 4. PERSISTENCE SEMANTICS

**FACT** — All store writes use `writeJsonAtomic` (`src/lib/fsx.ts:16-24`): write to `<path>.tmp.<uuid>` then `rename()`. This is atomic on POSIX. Crash between writeFile and rename leaves an orphan `.tmp.*` file but the target is unchanged.

**FACT** — `materializeArtifact` (`src/host/modules/activation/artifact.ts:142-182`):
1. Creates staging dir `<finalDir>.staging`
2. Writes files to staging
3. `rm(finalDir)` — **DELETES the live artifact**
4. `rename(stagingDir, finalDir)` — atomic replacement

**RISK** (`artifact.ts:176`): A crash between step 3 (rm) and step 4 (rename) permanently destroys the active artifact with no rollback path. On restart, `validateArtifact` fails and `refreshActivation` deactivates.

**FACT** — `createVersion` (`src/host/store.ts:181-203`) performs two separate `writeJsonAtomic` calls: first marking old active as `rolled-back`, then writing the new version. A crash between these writes leaves both versions potentially active (resolved by `getActiveVersion` returning the first match by number sort).

**FACT** — No transactional boundary across multi-step operations. The promotion flow touches version record, candidate status, artifact directory, and in-memory activation state — none are atomic together.

**FACT** — `listExperiences` (`src/host/store.ts:59-68` → `src/lib/fsx.ts:44-63`): every file in the directory is `stat`'d individually before sorting by mtime. Cost is O(N) where N = total files on disk, not O(limit). With 10k experiences this is ~10k sequential syscalls per call.

**FACT** — No schema migration path exists. `SCHEMA_VERSION = 1` is exported and reported by `evo_health` but never checked on read. `ARTIFACT_SCHEMA = 1` IS checked on load (`artifact.ts:207`).

## 5. SECURITY BOUNDARIES

**FACT** — Generated `plugin.js` (`artifact.ts:91-135`):
- Exports `name` (neutralized string) and `apply(ctx, config)` function
- `apply()` registers one tool that calls `ctx.get('evolutionRuntime').runCandidate()`
- **Never imports, requires, or evals any candidate source code**
- Only dynamic content: `JSON.stringify()` of neutralized strings and hardcoded versionId/toolName

**FACT** — `validateCandidateFileSet` (`builder/tools.ts:161-198`):
- Rejects paths containing `..`
- Rejects absolute paths
- Rejects `.sh`, `.exe` extensions
- Rejects duplicate file paths
- Requires `manifest.name`, `manifest.description`, `manifest.entryPoint`, `manifest.type`
- Requires at least one benchmark case

**HIGH RISK** (`sandbox/index.ts:113-123`): `NodeProcessSandbox` inherits full host PATH, has no namespace isolation, no network isolation, no filesystem isolation. It is a pure fallback with zero security guarantees. `getSandbox()` defaults to `BubblewrapSandbox`; `NodeProcessSandbox` is only instantiated in tests or if explicitly passed.

**MEDIUM RISK** (`benchmark/tools.ts:225`): `evo_benchmark_live` accepts `cwd` parameter that is joined with `tmpDir` without traversal check: `join(tmpDir, a.cwd)`. An attacker-controlled `cwd` of `"../.."` escapes the temp directory.

**MEDIUM RISK** (`artifact.ts:225`): `validateArtifact` reads `manifest.entryPoint` via `join(artifactFilesDir, entryPoint)` without checking for `../` traversal. A tampered manifest could reference paths outside the artifact dir.

**LOW RISK** (`sandbox/index.ts:74-79`): `SandboxExecOptions.readOnlyMounts` / `readWriteMounts` are passed directly to `bwrap --ro-bind` / `--bind` without validation. Internal API only; not exposed by `evo_sandbox_exec` tool.

**LOW RISK** (`sandbox/index.ts:64-65`): `--proc` and `--dev` mounted in bwrap without further filtering. PID namespace (`--unshare-pid`) helps but doesn't prevent host info access via `/proc`.

## 8. FAILURE MODES

### CRITICAL
1. **Promotion mounts before policy gate** (`promote/tools.ts:66→84`): A candidate that fails `beats_active` can still have its tool mounted in the host. The tool remains active until the next promotion/rollback/boot. **Fix**: Move `runPromotionPolicy` before `activateVersion` in the promotion flow, or add `deactivate()` on policy rejection.

### HIGH
2. **Artifact destruction window** (`artifact.ts:176`): Crash between `rm(finalDir)` and `rename(stagingDir, finalDir)` permanently loses the active artifact. On restart, activation fails gracefully but the version record is orphaned.
3. **Version attribution TOCTOU** (`auto-experience/index.ts:534`): `activationState().activeVersionId` is read at observation-recording time, not at turn-start time. A promotion/rollback between `turn/end` and `addExperience` mis-stamps the experience record. This corrupts degradation detection for both the old and new version.
4. **NodeProcessSandbox has zero isolation** (`sandbox/index.ts:113-123`): If bwrap is unavailable and any code path uses NodeProcessSandbox without checking `isAvailable()`, candidate code runs with full host access.

### MEDIUM
5. **Lifecycle limits unenforced**: `maxRecords`, `retentionDays`, `maxActive` are config keys with no enforcement. Store grows unbounded.
6. **No cross-step transaction**: `createVersion` + `updateCandidate` + `materializeArtifact` + `refreshActivation` are four independent operations. A crash between any two leaves partial state.
7. **Concurrent promotions**: Two `createVersion` calls can compute the same `nextNumber` and overwrite each other's version record.
8. **Path traversal in benchmark tools**: `evo_benchmark_live` and `evo_benchmark_ab` accept `cwd` without traversal validation (`benchmark/tools.ts:225`).
9. **Manifest entryPoint not validated for traversal**: `validateArtifact` joins `entryPoint` without `../` check (`artifact.ts:225`).
10. **Simulated evidence bypasses beats_active**: `runPromotionPolicy` skips comparative check when `candidateLatest.mode === 'simulated'`.

### LOW
11. **Orphan `.tmp.*` files**: `writeJsonAtomic` crash leaves temp files that are never cleaned up (slow disk leak, not correctness bug).
12. **`evo_observe_state` misreports observed count**: Reports ring buffer size (≤50, resets to 0 on boot) instead of stored experience count.
13. **Pattern dedup by description string**: Two unrelated patterns with identical description text cause the second to be silently dropped.

## 12. RECOMMENDED NEXT SINGLE MISSION

### Mission: Fix promotion gate order + add lifecycle limit enforcement

**Rationale**: Gap #1 (promotion mounts before policy gate) is the highest-severity defect — it allows unvetted candidate code to run in the host. Gap #2 (lifecycle limits) is the second-highest — it causes unbounded growth and latency degradation. Both are independent, low-risk fixes that address the most dangerous gaps simultaneously.

**Scope**:
1. Reorder `promote/tools.ts`: call `runPromotionPolicy` BEFORE `activateVersion`. If policy rejects, return error without mounting. If policy passes, then call `activateVersion`.
2. Add `deactivate('policy rejection')` in the error path of `evo_promote` to unmount any already-mounted artifact from the probe call.
3. Add a `prune()` method to `EvolutionStore` that removes experiences older than `retentionDays` and caps total at `maxRecords`.
4. Call `prune()` after each `addExperience` and `addBenchmark` call.
5. Add tests: (a) promotion rejection does not mount, (b) lifecycle limit enforcement, (c) pruning preserves newest records.

**Out of scope**:
- Version audit trail (separate mission)
- Schema migration (separate mission)
- Version attribution TOCTOU fix (separate mission — requires session event contract change)
- Concurrent promotion race (separate mission — requires locking)

**Acceptance criteria**:
- `evo_promote` with a candidate that fails `beats_active` returns `{ ok: false }` and `activationState().activeVersionId` is unchanged
- After 10,001 experiences are recorded with `maxRecords: 10000`, `listExperiences(10000)` returns exactly 10,000 (the newest)
- `evo_observe_state.storedExperiences` reflects the post-prune count
