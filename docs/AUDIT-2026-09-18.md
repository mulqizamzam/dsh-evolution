```
src/host/
├── index.ts          apply() → boot() → module loop → activation refresh

    ├── experience/   evo_experience_record, _list, _inspect
```

## 5. Current State Model and Persistence Behavior

### Storage Layout
```
$DSH_HOME/dsh-evolution/
├── experiences/    (append-only, one JSON file per record, ID-named)
├── patterns/       (append-only, one JSON file per pattern)
├── candidates/     (read-write, JSON metadata + optional files subdirectory)
├── benchmarks/     (append-only, one JSON file per run)
├── versions/       (read-write, but treated as immutable by convention)
└── tmp/
```

### Atomicity Guarantees
- `writeJsonAtomic()` writes to `<path>.tmp.<uuid>` then `rename()` — atomic on POSIX.
- `materializeArtifact()` uses a `.staging` subdirectory + rename — atomic promotion.
- `rollbackVersion()` does two writes (deactivate old, activate new) — not atomic as a pair, but each individual write is atomic.

### Concurrency
- **No locking.** Concurrent writes to the same file would corrupt via race on read-modify-write. However, the store is single-process (Node.js event loop), so in practice only one operation runs at a time within a process. Cross-process contention is not guarded.
- `listExperiences(500)` sorts by mtime but has no lock — a concurrent write could appear or disappear mid-list.

### Failure Recovery
- Corrupted JSON → `readJsonSafe` returns `null` (skips the record).
- Missing directories → `ensureStateRoot` creates them.
- Process crash mid-write → `.tmp.*` files are left on disk but never read (no cleanup).
- Stale `.staging` directories from failed promotions are overwritten on next promotion (rm + mkdir).

### Live State (as-of-audit)
- **137 experiences** (auto-recorded turns from active sessions)
- **22 patterns** detected
- **4 candidates** (all `promoted` status)
- **3 versions**: v1 (rolled-back), v2 (rolled-back), v3 (active, `turn-efficiency-tracker`)
- **4 benchmark runs**

### Duplicate Handling
- Patterns: dedup by exact description text match (`existingDescriptions.has(p.description)`). Two patterns with identical descriptions but different evidence are collapsed.
- Experiences: **no dedup**. Identical turns recorded twice produce two separate records.
- Candidates: **no dedup**. Same description can produce multiple candidates.

### Malformed Input Handling
- Tool arguments are type-coerced (e.g., `typeof a.success === 'boolean' ? a.success : false`).
- LLM response parsing handles markdown fences, trailing commas, missing fields.
- Artifact validation checks schema, tool-name shape, entry point presence.
- **Gap**: No validation that `patternIds` in `evo_builder_generate` actually exist before calling the LLM — the tool filters to matching patterns and returns `{ ok: false, error: 'no matching patterns found' }` if none match, but does not validate id format.

## 7. Security and Isolation Observations

### Sandbox
- **Primary**: `BubblewrapSandbox` — uses `bwrap` for namespace isolation (PID namespace, no network by default, tmpfs /proc, read-only binds for /usr, /bin, /lib, /etc).
- **Node binary workaround**: `dirname(process.execPath)` is bound read-only so nvm/volta/fnm-managed Node works inside the sandbox.
- **Fallback**: `NodeProcessSandbox` — no isolation, just `spawn`. Used when bubblewrap is unavailable.
- **Network**: Default deny; explicit `allowNetwork: true` opt-in.

### Candidate File Safety
- Path traversal rejected (`..` in path → error).
- Absolute paths rejected.
- Unsupported extensions rejected (only `.ts`, `.js`, `.json`, `.md`, `.yml`, `.yaml`, `.txt`).
- `.sh` and `.exe` explicitly rejected.
- Duplicate file paths rejected.
- `plugin.js` (the loaded artifact) is **host-authored** and imports nothing — candidate code only executes in the sandbox.

### Untrusted Data
- LLM response is parsed and validated before being used.
- `neutralizeDeep()` sanitizes all tool output (strips undefined, cycles, non-JSON-safe values).
- **Gap**: The LLM system prompt (in `buildSystemPrompt()`) is hardcoded and not parameterized — no injection vector, but also no way for a candidate to request special privileges.

## 8. Benchmark / Promotion / Rollback Analysis

### `evo_benchmark_run` (simulated)
- Computes metrics from ALL stored experiences (up to 500).
- Compares against candidate's `benchmarkConfig`.
- Records `mode: 'simulated'`.
- **Critical gap**: The "baseline" is the entire experience store, not a specific prior version. There is no concept of "metrics from v1 experiences" vs "metrics after v2 activation." The benchmark is a snapshot of the store, not a controlled experiment.

### `evo_benchmark_live`
- Writes candidate files to temp dir.
- Executes user-provided `command` in sandbox.
- Records `mode: 'live'` with actual exit code and timing.
- **Gap**: No comparison to baseline — a single pass/fail, not a delta.

### `evo_benchmark_ab`
- Proper A/B: runs both baseline and candidate N times each.
- Computes deltas on success rate, score, error rate, latency.
- Verdict based on `DEFAULT_PROMOTION_POLICY`.
- **Strength**: This is the only path that produces comparative evidence.

### `evo_promote_decision`
- Requires `mode: 'live'` unless `allowSimulated: true`.
- 5 policy gates: benchmark_passed, min_runs, success_improvement, max_regression, latency_multiplier.
- Returns structured evidence with per-gate pass/fail.

### `evo_promote`
- Order: materialize → validate → preflight (sandbox) → createVersion → updateCandidate → refreshActivation.
- Preflight fails before version is created if artifact is broken.
- **Verification**: `test/activation.spec.ts` confirms broken candidates never become versions.

### `evo_rollback`
- Flips status on two version files.
- Disposes mounted fiber immediately.
- Subsequent `evo_activation_status` reflects the new active version.

### Known Issue: `maxRecords` / `retentionDays` Not Enforced
- `config.ts:32` declares `experience.maxRecords: 10000` and `retentionDays: 90`.
- `store.ts` has no trim logic.
- README acknowledges: "declared but not enforced."
- Live state: 137 experiences and growing with no cap.

## 10. Known Gaps and Risks

### HIGH — Evidence Chain Broken (Invariant #4, #11)
**File:** `src/host/modules/analyze/tools.ts:34`, `src/host/modules/builder/tools.ts:388`  
**Problem:** Patterns and LLM-generated candidates store `evidenceIds: []`. A promoted version cannot be traced to the experiences that caused it. The `patternIds` field on candidates points to patterns, but those patterns have no `evidenceIds` pointing to experiences.  
**Impact:** Violates P13 (traceability) and the core design principle "evidence-based evolution."  
**Fix:** `detectPatterns()` should populate `evidenceIds` with the IDs of experiences matching the pattern signature.

### HIGH — No Experience Deduplication or Lifecycle
**File:** `src/host/store.ts` (no trim logic)  
**Problem:** 137 experiences on disk, growing without bound. `maxRecords` and `retentionDays` are dead config keys.  
**Impact:** Disk growth unbounded. `listExperiences(500)` in analysis always returns only the 500 most recent, silently dropping older data. Patterns based on older experiences are invisible.  
**Fix:** Implement trim in `addExperience()` or periodic cleanup.

### MEDIUM — Simulated Benchmark Is Not Real Evidence
**File:** `src/host/modules/benchmark/tools.ts:102-108`  
**Problem:** `evo_benchmark_run` computes metrics from the entire experience store as a "proxy population." This is not a controlled experiment — it's a statistical summary of past turns. A candidate that improves future performance cannot be distinguished from one that merely matches historical averages.  
**Impact:** The `simulated` evidence path can produce a `passed: true` result that has no causal link to the candidate. The promotion gate correctly requires `live` evidence by default, but `allowSimulated: true` bypasses this.  
**Fix:** Either remove the simulated path entirely, or document it as "baseline estimation only" and prohibit its use in promotion decisions.

### MEDIUM — End-to-End Outcome Not Measured (P6)
**File:** `src/host/modules/benchmark/tools.ts`  
**Problem:** The benchmark command is arbitrary. A candidate that passes `echo hello` gets `passed: true` but does nothing for DSH. There is no hook that measures "did DSH actually improve after this candidate ran?"  
**Impact:** P6 is not supported. A malicious or buggy candidate could pass all benchmarks while degrading real DSH performance.  
**Fix:** Add a post-activation observation window that compares metrics before/after promotion.

### MEDIUM — Auto-Cycle Dead by Default
**File:** `src/host/config.ts:48-51`  
**Problem:** `generation.enabled: false`, `promotion.enabled: false`, `minExperiences: 20`, `minOccurrences: 5`. The autonomous loop will detect patterns but never generate or promote. An operator must manually enable three flags AND configure an LLM endpoint to get autonomous evolution.  
**Impact:** P7 is not satisfied out of the box. The system is effectively manual-mode by default.  
**Fix:** This is intentional (conservative defaults), but should be documented as a configuration requirement, not an oversight.

### LOW — Version String Inconsistency
**File:** `package.json:3`, `src/host/index.ts:23`, `src/host/modules/status/index.ts:48`  
**Problem:** All say `0.1.0` but git history shows `v0.3.0` as the latest release tag (commit `c9ba320`). Live versions are `v1`, `v2`, `v3`.  
**Impact:** Confusion between plugin version (0.1.0) and evolution version (v1, v2, v3). Not a bug, but a documentation/naming inconsistency.  
**Fix:** Align or rename to clarify distinction.

### LOW — State Root Shared Between Test and Production
**File:** `src/host/lib/home.ts` (resolveStateRoot)  
**Problem:** Both the `evo-live` test profile and the `web` production profile write to `$DSH_HOME/dsh-evolution/`. Tests that use `mkdtemp` in `/tmp` are isolated, but the live `web` profile's state is the same directory the operator uses.  
**Impact:** Test runs against the live state root could interfere with production data (though no test currently does this).  
**Fix:** Document explicitly or add a test-only root override.

### LOW — `createVersion` Not Atomic
**File:** `src/host/store.ts:165-186`  
**Problem:** `createVersion` writes two files: first the deactivated old version, then the new active version. A crash between these two writes leaves two `status: 'active'` versions.  
**Impact:** Minor — the next `getActiveVersion()` call uses `.find(v => v.status === 'active')` which returns the first match (arbitrary if two exist).  
**Fix:** Use a staging file + rename, same as `materializeArtifact`.

## 11. Highest-Value Next Mission

**Task:** Fix the evidence chain — connect patterns to their source experiences and candidates to both patterns and experiences.

**Why this is highest-value:**
1. It directly addresses the most critical invariant violation (Invariant #4: "Candidate changes have explicit provenance and evidence").
2. Without traceability, P13 ("Keep every evolution decision traceable") is not met.
3. It enables all downstream guarantees: if you can't trace a pattern back to experiences, you can't audit why a candidate was generated, and you can't detect duplicate or stale evidence.
4. The fix is localized (two files) and has clear acceptance criteria.

**Specific changes required:**
1. In `analyze/tools.ts:34`, replace `evidenceIds: []` with the IDs of experiences that match the pattern's signature (the `experiences` array is already available in `detectPatterns()`).

## Summary

**What works:**
- Core CRUD on all entity types (experiences, patterns, candidates, benchmarks, versions).
- Append-only experience storage with auto-observation.
- Pattern detection with deduplication.
- Candidate generation via LLM (when host provides llm service).
- Three benchmark modes: simulated, live, A/B.
- Deterministic promotion gate that rejects simulated evidence by default.
- Artifact materialization with pre-flight sandbox validation.
- Boot-time and runtime activation/rollback.
- Sandbox isolation via bubblewrap (with Node binary workaround).
- 153 passing tests covering the happy paths.

**What is broken or incomplete:**
1. **Evidence chain** — patterns and LLM-generated candidates have empty `evidenceIds`. (HIGH)
2. **No experience lifecycle** — records grow without bound; `maxRecords`/`retentionDays` are dead config. (HIGH)
3. **Simulated benchmarks** are statistical summaries, not controlled experiments. (MEDIUM)
4. **No post-promotion regression monitoring.** (MEDIUM)
5. **Autonomous loop is disabled by default** (intentional but limits P7). (MEDIUM)
6. **Version string inconsistency** (plugin 0.1.0 vs git v0.3.0). (LOW)
7. **createVersion not atomic** (two writes without staging). (LOW)

**Highest-value next step:** Fix the evidence chain (finding #1 above). This is a small, localized change with outsized impact on traceability and trust in the system.
